# ADR-003: 既定を数える Box にする

Status: 方向を採用(2026-11-14、ユーザー決定)。**成立性の確認(下の「確認」)が通るまでは、仮の採用。** 実装は 0。
Date: 2026-11-14
Scope: 普通の Box の所有を、非原子の参照カウントで持つ方向と、その確認・未決点・作業の順をここへ集約する。

[ADR-002](adr-002-explicit-ownership-and-compiler-migration.md) の「全 Box への暗黙 RC は採用しない」(17 行、「不採用と理由」)を、この ADR が見直す。
確認が通るまで、ADR-002 の本文と [ownership.md](../../reference/language/ownership.md) は書き換えない。今の main の動作も変えない。
確認が通らなかった時は、この ADR を不採用にして ADR-002 へ戻る。

## 決めた事

1. 普通の Box は、非原子の参照カウントで持つ。`=`・引数・field への格納・`return` は、持ち分を足すか移す。source に印は書かない。
2. `local b = a` の後の `b.x = 1` は、`a` からも見える。これを受け入れる。
3. GC は入れない。`fini` は、最後の持ち主が消えた時に、決まった順で走る。
4. ADR-002 の `edit` の実装(型付き Place)と 3b(明示 `move` への切替)は、始めない。
5. 強い循環は回収しない。終了の時に残った object を型ごとに報告し、その報告を test の失敗にする。`fini` を持つ object が残ったら誤りにする。

## 文法の見込み(確認が通った後に、ownership.md §0 と EBNF で確定する)

| 書く物 | ADR-002 | この ADR |
| --- | --- | --- |
| `local r = node` | 借りるだけ | `r` も持ち主(+1) |
| 渡して保存する | `eat(move node)` | `eat(node)` |
| 2 か所で持つ | `share new T()`・`share move x`・`share h`(読むだけ) | 印なし。書き換えもできる |
| 引数を書き換える | `edit x: T` と `f(edit x)` | 未定(下の 2) |
| field に入れる | `me.f = move x` | `me.f = x` |
| `birth(take x: T)` | 要る | 要らない |
| `Shared<T>`、`: T from me` | 要る | 要らない |

残す物: `copy`(中身の複製)、`weak`(循環を切る)、`take place`(場所から抜いて null にする)、`fini`。

## 未決(確認の後、selfhost の code を書く前に決める)

1. **`move` を残すか。** 残す案: 書いてもよい印で、元の binding を使えなくし、+1 を省く。消す案: `=` の意味を 1 つにする。
2. **`edit` を検査として残すか。** 「`edit` の印が無い引数への書き込みを拒否する」検査を入れるなら、定義側の `edit x: T` が残る。
3. **ユニークな型を入れるか。** 型の宣言で「ユニーク」とした型だけ数を持たず、ADR-002 の検査を受ける形。入れるなら、数える型を後で変えるのは書き直しになるので、selfhost の前に決める。材料は、selfhost のコンパイラに「共有してはいけない型」が実際に幾つあるかの調査。境目の決まり(ユニークな Box を数える Box の中へ入れた時)も、ここで決める。
4. **header の大きさ。** 40 バイトのまま数えられたのは、`fini` も weak も無い direct 配置の型だけ。それ以外の Box の置き方。
5. 走査している間の Map・配列の書き換えを Fault にするか。
6. 今 main で動く `move`・`share`・`birth(take x)` の source の移し方。

## 根拠: 実物の EXE の測定(2026-11-14)

入力は `apps/ownership-tree-bench-typed/main.hako` を深さ 14 と 18 にした物(木を作り、たどり、片付ける。共有は無い)。direct 配置、node は 40 バイト。Ryzen 7 5825U、CPU 固定、thread 1 本。全部の版を交互に 12 回測った中央値(ns/ノード)。測定の branch `rc-measure` は main に入れていない。

| 版 | 数える所 | 深さ 14 | 比 | 深さ 18 | 比 |
| --- | --- | ---: | ---: | ---: | ---: |
| A40 | 数えない(今の main) | 50.34 | 1.00 | 60.89 | 1.00 |
| Re40 | 解放の所だけ | 49.72 | 0.99 | 60.10 | 0.99 |
| Rb-arg | 読んで local に持つ時。引数は数えない | 50.68 | 1.01 | 60.72 | 1.00 |
| Rn-arg | 上に加えて、格納の時 | 52.27 | 1.04 | 62.38 | 1.03 |
| Rb-all | 読む時と、引数を渡す時 | 54.66 | 1.09 | 64.82 | 1.07 |
| Rn-all | 全部(何も省かない) | 56.50 | 1.12 | 66.54 | 1.09 |

- 何も省かずに全部数えると 9〜12% 遅い。「引数は数えないで渡す」決まり 1 つで 2.5〜4% まで戻る。
- header を 8 バイト増やすと、深い木で +21%、memory は約 1.3 倍(別の回の測定)。header の語を時分割(生きている間は数、片付けの間は parent)にすると、40 バイトのまま数えられた。
- **限界:** +1・−1 は、人が場所を決めて置いた。コンパイラが自動で置ける証拠ではない。入力は 1 つ。共有がある入力、weak、`fini` を持つ型、文字列・配列・Map が多い入力は測っていない。
- コンパイラに自動で置かせる試みは止まった。field から読んだ値は別名として扱われ、片付けの義務を持たないため。「借りた値 → 寿命の範囲 → Normal と Fault の出口」をつなぐ表現が要る。

3 つの AI(ChatGPT Pro、Fable、Gemini)に、同じ数字で相談した。3 つとも「既定を数える Box にして、`edit` は作り始めない」で一致した。ユニークな型は割れた(selfhost の前に要る / 後で足す / 要る型が出た時だけ)。

## 確認(この ADR を本採用にする条件)

小さい範囲で、コンパイラが自動で +1・−1 を置く。次の全部を満たしたら、本採用にする。

1. 上の測定の入力で、+1・−1 の回数が、手で置いた表(Rn-arg の版)と同じになる。
2. Fault を注入しても、残る object が 0 個で、早い解放も 2 回の解放も無い。
3. 次の 4 つの形が、決まりどおりに動く。
   - `f(a.child)` の中で `a.child` を消す。
   - `f(a.child, g())` の `g()` が `a.child` を消す。
   - `f(a.child, g())` の `g()` が Fault する。
   - `f` に渡した値を、`f` が別の場所へ保存する。
4. 共有がある入力(同じ object を 2 か所から持つ)で、残る object が 0 個で、`fini` が 1 回だけ、決めた順で走る。
5. 生成後の MIR の独立の検証が、+1・−1 の対応を確かめる(数の検査を Home の記録だけにしない)。

引数の決まり: field・配列の要素・一時的な式から渡す値は、呼ぶ側が評価した時に +1 して、呼び出しの終わりに −1 する。呼ばれた側は数えない。保存する時だけ、保存先の持ち分を足す。

新しい公開 MIR・opcode・ABI・descriptor が要ると分かった時は、作る前にユーザーが決める。
