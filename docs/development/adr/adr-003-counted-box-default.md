# ADR-003: 既定を数える Box にする

Status: 方向を採用(2026-11-14、ユーザー決定)。**成立性の確認(下の「確認」)が通るまでは、仮の採用。** 実装は、片付けの物理の形(段 B)まで main に入った。自動の +1・−1 は、まだ無い。
Date: 2026-11-14
Scope: 普通の Box の所有を、非原子の参照カウントで持つ方向と、その確認・未決点・作業の順をここへ集約する。

[ADR-002](adr-002-explicit-ownership-and-compiler-migration.md) の「全 Box への暗黙 RC は採用しない」(17 行、「不採用と理由」)を、この ADR が見直す。
確認が通るまで、ADR-002 の本文と [ownership.md](../../reference/language/ownership.md) は書き換えない。今の main の動作も変えない。
確認が通らなかった時は、この ADR を不採用にして ADR-002 へ戻る。

## 決めた事

1. 普通の Box は、非原子の参照カウントで持つ。`=`・引数・field への格納・`return` は、持ち分を足すか移す。source に印は書かない。
2. `local b = a` の後の `b.x = 1` は、`a` からも見える。これを受け入れる。
3. GC は入れない。`fini` は、最後の持ち主が消えた時に、決まった順で走る。
4. ADR-002 の `edit` の実装(型付き Place)と 3b(明示 `move` への切替)は、始めない。
5. 強い循環は回収しない。終了の時に残った object を型ごとに報告し、その報告を test の失敗にする。`fini` を持つ object が残ったら誤りにする。

## 文法の見込み(確認が通った後に、ownership.md §0 と EBNF で確定する)

| 書く物 | ADR-002 | この ADR |
| --- | --- | --- |
| `local r = node` | 借りるだけ | `r` も持ち主(+1) |
| 渡して保存する | `eat(move node)` | `eat(node)` |
| 2 か所で持つ | `share new T()`・`share move x`・`share h`(読むだけ) | 印なし。書き換えもできる |
| 引数を書き換える | `edit x: T` と `f(edit x)` | 印なし(仮の決定。下の「未決」の 2) |
| field に入れる | `me.f = move x` | `me.f = x` |
| `birth(take x: T)` | 要る | 要らない |
| `Shared<T>`、`: T from me` | 要る | 要らない |

残す物: `copy`(中身の複製)、`weak`(循環を切る)、`take place`(場所から抜いて null にする)、`fini`。`move`・`edit` は、普通の Box では書かない(語は予約のまま)。

## 未決(確認の後、selfhost の code を書く前に決める)

### 1・2・3 は、仮に決めた(ユーザー決定 2026-11-15)

`move`・`edit`・ユニークな型は、1 つの相談でまとめて決めた。3 つの AI(ChatGPT Pro、Fable、Gemini)が、別々に答えて、同じ形を選んだ(private の記録)。確認が通った時に、「仮」を外す。

1. **`move`: 普通の Box では使わない。** `=`・引数・格納の意味は 1 つにする。この ADR の引数の決まりでは、local を渡す時は数えず、+1 は呼ばれた側が保存する所で起きるので、呼ぶ側の `move` で省ける +1 は無い。「渡した後は使わない」は、名前を付けずに渡す・scope を切る・`take place` で書く。
2. **`edit`: 入れない。** 値打ちが無いと決めたのではなく、必須にする材料が、今は無い(間違いの実例は見つかっていない)。ちゃんと守るには、別名・getter の結果・素通しの引数まで「書く権限」を追う仕組みが要り、印を足すだけでは済まない。
3. **ユニークな型: 入れない。** 今の `.hako` で候補になる型は、実際には 2 か所から持たれている。入れると、正しく動いている設計の書き直しになる。
4. **今決めて、後で変えない事: 普通の Box は、複数の場所から持てて、どこからでも書き換えられる。** 後から `edit` の検査やユニークな型を足す時は、今ある普通の Box の意味を変えずに、新しい宣言(新しい型に付ける宣言、新しい検査)として足す。
5. **語は予約のまま残す。** `move`・`edit`・`take` は、後で足す時のために、名前として使えないままにする。今 main で動く `move` の実装も、急いで消さない。足す時は、同じ語に違う強さの意味を持たせない(ADR-002 の `edit` は「場所を 1 人だけが借りる」意味で、数える Box の引数の印とは強さが違う)。
6. **型の無い値を、黙って `Dynamic` にしない。** 型が決まらない時は、拒否する。`Dynamic` は、書いた時だけ。
7. **field の型は必須。相互の参照(親 ↔ 子、block ↔ block、scope ↔ symbol)は ID で持つ。**
8. **所有の文法の切替は 1 回。今ある `.hako` は、一度には移さない。** 所有の印を使う `.hako` は 3〜4 file だけなので、文法の切替で直す source は小さい。重いのは、型の注釈と、Map の書き方の方。

後から足す合図(今は、どれも出ていない): 読むだけのつもりの引数を書き換える間違いが、実際に繰り返し起きた(→ `edit` の浅い検査から)。「閉じた後は使えない」「1 つしか開けない」を、コンパイルの時に止めたくなった(→ ユニークな型か、状態を区別する型)。2 か所から持たれてはいけない資源が出た、ある型でだけ数える費用が重いと測れた(→ ユニークな型を、新しい型として)。

### 1・2・3 の中で、まだ決めていない事

- **A. selfhost のコンパイラの data の持ち方。** 3 つの答えが割れた: 新しい code は型付きの箱と enum で書く / 固定の項目から箱へ、段階で移す / まず Map のまま selfhost を通して、後で箱へ。今の `.hako` のコンパイラは約 5.5 万行で、Map の書き方は `mirbuilder`(全体の 41%)に集まる。Rust 側の MIR builder は、test を除いて約 75 万行(2026-11-15 に数えた)。**何を、どれだけ書くかの調査(builder の大きさ)が先に要る。**
- **B. 内部の関数の引数と戻り値の型。** 必須にする(2 つの答え)か、推論する(1 つの答え)か。今ある `.hako` で型が書いてある引数は 0.2%(約 6,000 個のうち 12〜13 個)。数える Box では、全部の Box の引数が同じ契約になるので、所有の宣言のために型を必須にする理由は、1 つ減っている。
- **C. 今ある `.hako` を、明示した古い道のまま動かし続けるか、移すか。** A の答えで決まる。黙って古い道へ落ちる形は、採らない。
- **箱どうしの `==`(同じ object か)。** ownership.md §0 は「切替で compile error」としている。数える Box では意味があり、今の `.hako` も印の箱の比べに使っている。
- **`record` をやめた決定(ADR-002「凍結」)の見直し。** 別名から書ける世界では、「変わらない data」の置き場所の値打ちが戻る。
- **新しい EXE の経路で、enum と `match` がどこまで動くか。** 確かめていない(今の `.hako` のコンパイラは、enum が 4 個、`match` が 0 か所)。式の `take place` は、まだ 1 形もつながっていない。

### 4. header の大きさ

**仮に決めた(ユーザー決定 2026-11-15。ChatGPT Pro の答えの形。private の記録)。**
   - 普通の Box は、今の 16 バイトの時分割の header のまま。
   - 弱い参照の管理用の cell は、その object へ弱い参照が実際に作られた時だけ付ける。弱い参照は、`fini` の前に無効にする。
   - `fini` を持つ Box は、数を 1 に戻さない。強い数は 0 のまま、外へ出せない FinalizerLease で自分を使う。
   - 配列・Map・文字列は、Retain・Release の契約を同じにする。数の置き場所は、置き方ごとに持つ。
   - malloc の枠の訂正: glibc の枠は「要求 + 8 を 16 の倍数へ切り上げ」。32 → 48、40 → 48、48 → 64(この機械の glibc 2.35 で確かめた)。header を 8 バイトに減らして node を 32 バイトにしても、枠は 48 のまま。だから、header を小さくする案より先に、slab の比較をする(後の速さの回)。
   - 実装は、確認(段 C0〜G)の後。確認の範囲は、`fini` も weak も無い型のまま。条件は下の「後の回の条件」。
   - この中で、まだ決めていない事:
     - cell への届き方(runtime の索引から引く形か、header の 1 語目を「数か cell への pointer」にする形か)。答えは索引を先に勧めている。
     - 「弱い参照を作った事がある」印の置き場所。header の 2 語目に、今は空きが無い。
     - 数のビット数(今は 64 のまま。32 にする案は別の配置の改善)。
     - 型の id を header から外す案と、8 バイトの header。
     - `fini` の中で、ほかの子の object を持つ操作をどこまで許すか。
     - 配列・Map・旧い置き方をまたぐ片付けを、再帰なしで続ける形。
### そのほか

5. 走査している間の Map・配列の書き換えを Fault にするか。
6. 今ある source を、最後の文法へ移す方法。今 main で動く `move`・`share`・`birth(take x)` の形と、既存の `.hako`(コンパイラと apps)の両方。

## 根拠: 実物の EXE の測定(2026-11-14)

入力は `apps/ownership-tree-bench-typed/main.hako` を深さ 14 と 18 にした物(木を作り、たどり、片付ける。共有は無い)。direct 配置、node は 40 バイト。Ryzen 7 5825U、CPU 固定、thread 1 本。全部の版を交互に 12 回測った中央値(ns/ノード)。測定の branch `rc-measure` は main に入れていない。

| 版 | 数える所 | 深さ 14 | 比 | 深さ 18 | 比 |
| --- | --- | ---: | ---: | ---: | ---: |
| A40 | 数えない(今の main) | 50.34 | 1.00 | 60.89 | 1.00 |
| Re40 | 解放の所だけ | 49.72 | 0.99 | 60.10 | 0.99 |
| Rb-arg | 読んで local に持つ時。引数は数えない | 50.68 | 1.01 | 60.72 | 1.00 |
| Rn-arg | 上に加えて、格納の時 | 52.27 | 1.04 | 62.38 | 1.03 |
| Rb-all | 読む時と、引数を渡す時 | 54.66 | 1.09 | 64.82 | 1.07 |
| Rn-all | 全部(何も省かない) | 56.50 | 1.12 | 66.54 | 1.09 |

- 何も省かずに全部数えると 9〜12% 遅い。「引数は数えないで渡す」決まり 1 つで 2.5〜4% まで戻る。
- header を 8 バイト増やすと、深い木で +21%、memory は約 1.3 倍(別の回の測定)。header の語を時分割(生きている間は数、片付けの間は parent)にすると、40 バイトのまま数えられた。
- **限界:** +1・−1 は、人が場所を決めて置いた。コンパイラが自動で置ける証拠ではない。入力は 1 つ。共有がある入力、weak、`fini` を持つ型、文字列・配列・Map が多い入力は測っていない。
- コンパイラに自動で置かせる試みは止まった。field から読んだ値は別名として扱われ、片付けの義務を持たないため。「借りた値 → 寿命の範囲 → Normal と Fault の出口」をつなぐ表現が要る。

3 つの AI(ChatGPT Pro、Fable、Gemini)に、同じ数字で相談した。3 つとも「既定を数える Box にして、`edit` は作り始めない」で一致した。ユニークな型は割れた(selfhost の前に要る / 後で足す / 要る型が出た時だけ)。

## 確認(この ADR を本採用にする条件)

小さい範囲で、コンパイラが自動で +1・−1 を置く。次の全部を満たしたら、本採用にする。

1. 上の測定の入力で、+1・−1 の回数が、手で置いた表(Rn-arg の版)と同じになる。この入力では、field から読んだ値は全部 receiver か local で、呼ぶ側が持つ。local と fresh な値の引数は数えない。だから、下の引数の決まりの回数は Rn-arg と同じになる(`-all` の版は、呼ばれた側が数える別の形で、比べる相手ではない)。
2. Fault を注入しても、残る object が 0 個で、早い解放も 2 回の解放も無い。
3. 次の 4 つの形が、決まりどおりに動く。
   - `f(a.child)` の中で `a.child` を消す。
   - `f(a.child, g())` の `g()` が `a.child` を消す。
   - `f(a.child, g())` の `g()` が Fault する。
   - `f` に渡した値を、`f` が別の場所へ保存する。
4. 共有がある入力(同じ object を 2 か所から持つ)で、残る object が 0 個で、`fini` が 1 回だけ、決めた順で走る。
5. 生成後の MIR の独立の検証が、+1・−1 の対応を確かめる(数の検査を Home の記録だけにしない)。

引数と receiver の決まり: field・配列の要素・一時的な式から読んで、引数か receiver に使う値は、呼ぶ側が評価した時に +1 して、呼び出しの終わりに −1 する。持ち主の local と fresh な値は、そのまま渡して数えない。呼ばれた側は数えない。保存する時だけ、保存先の持ち分を足す。

確認の範囲: 型は direct 配置で `fini` も weak も無い物(`TreeNode`)。field の上書き(古い値の −1)は、今の Box に契約が無いので、範囲の外(拒否のまま)。

公開 MIR(ユーザー決定 2026-11-14): Box の参照の +1 と −1 を表す型付きの操作を、今ある Invoke の中へ足してよい。一番上の opcode は増やさない。`Shared` の操作は、数が runtime の別の表にあるので使わない。操作の名前と、Normal・Fault の決まりは、作る前に設計の案をユーザーが見る。独立の検証(`ownership_ssa`)は、今は持ち主が 1 人の前提なので、複数の持ち分を許す決まりへ広げる。これ以外の新しい公開 MIR・opcode・ABI・descriptor が要ると分かった時は、作る前にユーザーが決める。

調査(2026-11-14、読むだけ)で分かった事: 今の main の普通の Box は数えていない。`local b = a` は別名で、`b` を使う形は拒否される。`new Holder(a)`(birth が保存する形)は暗黙の move で、この ADR では +1 になり `a` も生きる(同じ書き方の意味が変わる。未決 6 に含める)。つなぐ先は、式の一時値の台帳と scope の出口の計画で、新しい持ち主は作らない見込み。

## 確認の進み

- 2026-11-15 段 B(Codex 実装、Opus 監査、統合済み): direct 配置の片付けが「数が 0 の時だけ中へ進む」形になった。alloc で header の 1 語目に 1 を入れ、release と End の root・子の入口で −1 する。0 になった時だけ parent と cursor を書く(時分割)。header 16 バイト、node 40 バイトのまま。MIR は変えていない。数は alloc の 1 だけなので、動作は前と同じ。
  - Opus の確認: 363 本の入力で結果と MIR が前と全部同じ。木の bench(direct 配置)を前と後の backend で作り、出力が同じ。機械語で、非原子の inline の減算と分岐を見た。lib の失敗 223 名は前と同じ集合。速さ(A40 との比 0.98〜1.00)、Fault の注入、数え上げは Codex が測った。
  - `volatile` は要らないと分かり、段 C0 で外した。数の読み書きの間に外の呼び出しも再入も無く、外しても取得・解放・Fault の順は同じ。
- 2026-11-15 段 C0(Codex 実装、Opus 監査、統合済み): 共通の式の結果が、型付きの Box の参照(借りか自分の物か、由来)を運ぶ。一時値の保存の列は 3 本から 1 本の順序付きの台帳になった。Box の持ち分の項目は場所だけあり、まだ取得する入力は無い。受理と MIR は変えていない。
  - 整形後の production +255 行、test −8 行。production の file は最大 777 行。
  - Opus の確認: 363 本の入力で結果と成功の MIR が前と全部同じ。木の bench の出力が同じ。機械語で `volatile` の無い非原子の減算を見た。lib の失敗 222 名は前の 223 名の部分集合。
  - 段 C で足す所は 6 つの責務(資格の判定、持ち分の取得、Release の投影、source と物理の照合、行き先への移転、操作の実装と独立の検証)。
- 操作と検証の設計: [counted-box-check-2026-11-15.md](../current/main/investigations/counted-box-check-2026-11-15.md)。**ユーザーが 2026-11-15 に承認した。** 決めた事:
  - 操作は `CountedBox::Retain` と `CountedBox::Release` の 2 つ。今ある Invoke の中に置く。
  - Retain は Fault しうる。数があふれる時は、足さずに Fault にする(wrap しない)。Fault の時は持ち分を得ない。
  - Release が、−1 と、0 になった時の片付けの両方を持つ。`ObjectEndIfOwned` を別に出して 2 回引く形にしない。
  - Retain は値を返さない。今ある Copy で別の slot を作り、その slot の Normal の辺に持ち分を付ける。
  - 残る確認: field から読んだ値を +1 して `return` する形(段 F)が、この形のままで閉じるかは未確認。新しい公開の形が要ると分かったら、そこで止めてユーザーが決める。
  - 検証は実行時の数を見ない。持ち分(token)が、全部の Normal・Fault の道で、ちょうど 1 回、移るか Release される事を見る。

- 2026-11-15 段 C(field への格納と、操作の実装): **止まった。main に入った code は無い。** Codex が試作し、指示書の「行数が見込みを大きく超えたら止める」条件で止めた。
  - field への格納をつなぐだけで、整形後 +426 行(見込みは +150〜300)。操作・検証の補助を入れた試作の全体は +841 行で、まだ birth の実際の格納と、独立の検証はつながっていなかった。
  - 増えた中心: 直接の配置の選択を上流へ運ぶ事、birth の元の格納を共通の式の評価へ映す事、呼ぶ側の暗黙の move を止める契約の受け渡し。
  - 分かった事: Copy の由来と持ち分は別の軸で、別名の根へ潰すと検証できない。格納した field の責任を、後の Fault まで検証が持つ必要がある。C の側は「呼ぶ側が持つ」前提の印を、実際の持ち主の印へ変える必要がある。plain と take を引数の表現だけでは区別できない(新しい公開 ABI が要るとは、まだ決まっていない)。
  - 記録は [counted-box-check-2026-11-15.md](../current/main/investigations/counted-box-check-2026-11-15.md) の 9・10 節。試作は repo の外に保存してある。
  - 次: 段 D へ進まない。段 C の作り方を、小さくする形に設計し直す(読むだけの回)。**これは「確認」の途中の結果で、通ったとも、通らなかったとも、まだ言えない。**

## 後の回の条件: 弱い参照と `fini`

確認(段 C0〜G)の後の回で、弱い参照と `fini` を持つ型を数える。その回は、次の 9 つを全部満たす(ChatGPT Pro の答えの probe。ユーザー決定 2026-11-15)。

| probe | 満たす事 |
| --- | --- |
| 弱い参照を作った後、最後の強い持ち分を Release する | 中身は片付き、弱い参照の cell だけが残る |
| `fini` の中で、自分への弱い参照を upgrade する | 失敗する。復活しない |
| `fini` の中で、最後の弱い token を捨てる | 片付けが、解放した後の cell を触らない |
| 解放した address を、別の object が使い直す | 古い弱い参照は、新しい object へつながらない |
| 2 つの親、または 2 つの field が、同じ子を持つ | 最初の −1 では子を変えない。最後の −1 で 1 回だけ片付ける |
| 親と複数の子の `fini` が Fault する | 決めた順、最初の Fault、残りの片付けを保つ |
| `fini` から `me` を保存する・capture する・持ち主として引数に渡す | source の検査と独立の検証が拒否する |
| Box → 配列 → Box → Map を深くつなぐ | 片付けが、深さの分の native stack を使わない |
| 弱い参照の cell の確保の失敗、Retain のあふれ | 得ていない持ち分を発行しない。元の責任を保つ |

片付けの順: 最後の持ち分を消費 → 弱い参照の upgrade を止める → cell から中身への対応を無効にする → header の 1 語目を parent に使う → `fini`・子・native の片付け → 中身を回収 → 弱い token が全部消えたら cell を回収。

作る順(答えの勧め): direct 配置の共有 → 弱い参照の cell → `fini` と FinalizerLease → 配列・Map・旧い置き方をまたぐ片付け。
