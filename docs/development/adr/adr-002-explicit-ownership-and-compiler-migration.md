## 採用する方向

所有操作を局所的に読めるようにし、単独所有を基本経路にする。
全Boxへの暗黙RC、最終使用位置による暗黙move、推論失敗時のDynamic化は採用しない。

1. `=` は右辺の結果を左辺へ格納する。
2. 所有値を手放す操作は `move`。複製はcopy契約を宣言した型だけ（`copy x`を`.copy()`へ綴り替えるかは保留）。
   共有の持ち分は前置き`share`で得る（2026-11-03改訂）: `share new T()`と`share move x`で共有を始め、`share h`で既存の`Shared<T>`の持ち分を増やす。裸の`share x`で普通Boxを手放すことはない。`Shared(...)`は接続時に退役し、`.share()`と`Shared.clone`は作らない。
3. 新しい所有値を返す式は直接渡せる（`cache.put(Image.load(p))`）。数値・Boolは暗黙コピーの値カテゴリで、サイズでは決めない。
   Shared handleは暗黙複製しない（2026-11-03改訂）: `move h`は増やさず移し、`share h`だけが一つ増やす。readと借用は増やさない。Sharedは当面読み取り専用で、共有変更とthread越えは別契約。
4. 引数は既定 `read`（書かない）。`edit` と `take` は定義側で宣言する。`edit`引数は呼出し側にも`edit`を書く（`rewrite(edit q)`、2026-11-03改訂）。receiverのread/edit借用は宣言から決まり、呼出し側に書かない。
   receiverの消費だけ呼出し側で明示する（`(move image).into_bytes()`）。
5. `return`は所有ローカル全体と新しい所有値に限りmove不要。借用値は、定義側で支持元を宣言した
   `from me` / `from <引数>` の結果だけ返せる（2026-10-30改訂。制約はownership.md §0）。
   その他の場所では最終使用でもmoveを明記し、ブロック末尾やbreakにも省略を広げない。
6. 一般の部分moveは禁止し、所有する親の直接fieldだけ`move`できる（条件は「前置きの所有操作」の行。2026-11-03）。nullableな場所からは前置き`take place`で取り出す（場所はnullになり、親は完全なまま）。`replace`は当面入れない（上書きは`me.body = move next`、nullable fieldの旧値は`take`と代入で受け取る）。containerの要素はAPIごとに契約を決める。

```hako
// 次期構文の説明例。今日のparser-liveの実行例ではない。
local p = new Point { x: 0, y: 0 }
local q = move p
local r = copy q
arr.push(move r)
arr.push(new Point { x: 1, y: 2 })
translate(edit q, 10)   // edit引数は呼出し側にも書く
return q
```

裸の `local b = a` は、自動コピーされない値なら所有するShared handleを含めread借用で、所有は動かず増えない（2026-11-03改訂。所有するなら`move`か`share`を書く）。field読み `local x = me.field` は注釈なしの `from me` 読み借用で、借用結果と同じ検査器が扱う。
`return q`の省略は全体ローカルと`take`引数に限る（`return move q`もエラーにはしないが、例は`return q`に揃える）。借用引数は返せず、fieldからは`return move n.left`で所有する親の条件に従う。
明示Dynamicは独立した契約として残す。静的検査を基本にすることと、Dynamicの禁止は別である。

| 前置きの所有操作 | 決定（2026-11-03。接続状況は2026-11-05に実測して更新（形ごとの表は`docs/reference/language/status-index.md`の「Ownership forms measured」）: `share`はlocal初期化式の3形まで接続済み（実測で再確認）で、`Shared(...)`と裸のShared ## コンパイラの責務

```text
parse / resolve / type + source intent
  -> 同一のsemantic CFGでownership・borrowを解析
  -> scope / Normal / FaultごとのEnd計画
  -> sole lower / MIR
  -> 変換後MIR・ABIの独立検証
  -> 最適化 / LLVM
```

MirBuilderはキーワードだけでなく、正確なPlace・Binding・型・引数契約・評価順・
Normal/Fault辺を保持する。unknownをTrivialにする既定値で新モデルを通さない。
検査は実際に獲得された所有責任について、全経路で移転またはEndがちょうど一回と証明する。
End挿入前は未消費を破棄義務として計画し、挿入後の検証で実際の消費を再確認する。
maybe状態はCFGの必要性がある場合だけdrop flagにし、loop世代とFault前後を区別する。

既存[Ownership SSA](../../../src/mir/ownership_ssa/README.md)はPHI辺移転・二重消費・
終了時の未処理を検査する狭い土台。本番callerは公開MIRのbackend capability検査（`src/mir/backend_capability.rs`の`verify_ownership_ssa_v1`呼出し）の1か所で、managed-call ABIと一般の借用検査は未対応（2026-11-05に呼出し元をgrepで確認）。
旧local plannerは未接続のまま退役済み（`80c87f4259`、READMEごと削除）。field/index/capture・一般Placeは対象外。借用の暗黙コピー処理は新規則へそのまま流用しない。
現在のMIR `CopyOwned`は同じobjectの独立owner tokenを作る命令で、source `copy`の複製ではない。
`DestroyOwned`の共通化には、型別終了処理・Fault・順序を残す。KeepAliveの生存支持や
ReleaseStrongの既存callerを名前変更だけで削除しない。
LLVM noaliasはeditの綴りから発行せず、実際の排他区間と到達可能なaliasを証明する。

暗黙copy/move、最終使用での省略、全Boxの暗黙RCは、局所的な意味とコストを曖昧にする。一般Box向けの`share x`、`.share()`、サイズで決める暗黙copy、本体からの借用結果推論も同じ理由で採用しない。Shared handleの暗黙複製も2026-11-03に同じ理由で廃止した。前置き`share`は、普通Boxをfresh結果か明示`move`でしか受けず借用Boxから所有を作らない形に限定して採用する（旧案も明示操作だったので、違いは明示性ではなく入力の限定にある）。
source `copy`を既存CopyOwnedへ単純対応させる案は、値の複製と共有を混同する。
毎stopのfixture/ADR作成や時間だけでの保留は採用せず、現行の1アプリ単位のRULESを維持する。
