# Normal root execution atomic cutover manifest D0

Status: design_stop — manifest only; semantic C0 is not open
Date: 2026-08-23
Decision: NORMAL-ROOT-EXECUTION-ATOMIC-CUTOVER-MANIFEST-D0
Parent: NORMAL-ROOT-EXECUTION-REFERENCE-ROUTE-CLOSURE-D0

## Six-line brief

Decision:
  Freeze one atomic C0 owner/file/test/guard manifest for the total
  App/ProgramRuntime relation, canonical source-plan consumer, Raw-only
  discard, retained/test terminals, and old-edge retirement.
Source authority + canonical issuer:
  Parser total-root issuer and route-specific consumers named by the parent
  D0; this card issues no new source or semantic product.
Non-authority:
  narrow Script-A/Main0 products, AST inventory, raw expansion, Builder state,
  work-plan bool, Recipe, MIR, compatibility retry, and disconnected P0/S0.
Fail-fast boundary:
  Before any semantic Rust, every in-bound parser-product terminal and every
  pre-terminal source extraction/reclassification edge has one named owner,
  one replacement, and one retirement proof.
Smallest next slice:
  Produce the exact atomic C0 manifest and reusable guard contract only.
Non-claims:
  No Rust implementation, fixture behavior change, production switch,
  fallback, compatibility expansion, or physical cleanup.

## Census boundary

This manifest covers:

```text
ParsedProgramWithCallableParameterSourceV1::new
  -> normal/default final-source transport
  -> canonical source-plan classification
  -> Raw-only reference discard
  -> retained/test terminals
  -> compatibility/source-backed extraction boundaries
```

It includes the six open C0 rows and the old pre-terminal edges listed in
`normal-root-execution-reference-route-closure-d0-2026-08-23.md`. It excludes
post-terminal Recipe/module/physical consumers and the already-sealed
AST-only fixture owner.

## Change

Freeze a table with these columns for every C0 edge:

```text
owner file + symbol
current caller/cardinality
new sole owner/consumer
replacement file + test file
reusable guard assertion
retirement condition
fallback/retry count
effect boundary
```

The manifest must bind, as one cutover:

```text
total App/ProgramRuntime issuer
exact final-transform preservation
normal/default consumer
canonical source-plan consumer
Raw-only Ready discard
retained/test required-field closure
compatibility/source-backed route split
old pre-terminal extraction and classifier callers = 0
```

Findings outside this declared boundary use the existing parking valve. Only
an edge that can reclassify, drop, consume, bypass, or be required by C0
acceptance blocks this card. Other findings record owner, evidence, reopen
trigger, and non-authority, then remain parked.

## Contract

```text
one parser total relation
  -> one exact transform-preserved relation
  -> one route-specific consumer
  -> one source-plan policy terminal
  -> named post-terminal consumer
```

The C0 manifest must prove before implementation that:

- no source-backed product exit can silently drop or reclassify the relation;
- parser-backed `NormalSourceSurfaceInventoryV1::collect` and
  `PreparedNormalSourcePlanInputV1` production callers have an explicit zero
  retirement target;
- Raw discard is private to the sealed Raw profile and cannot enter canonical
  source-plan;
- compatibility has no fabricated `Ready`, empty, or optional total product;
- every named consumer has exactly one production caller and typed terminal;
- old fallback/retry and second source-plan loan counts are zero;
- the manifest does not require a standalone caller-zero P0/S0 commit.

## Done

This design card closes only when:

1. all six in-bound C0 blockers from the parent 14-row inventory are listed;
2. each new issuer, consumer, transform handoff, and retired edge names an
   exact production file, focused positive/negative test file, and one guard;
3. the before/after caller census and fallback census are reproducible;
4. the parking classification is finite and no finding is unclassified;
5. the C0 commit order is atomic and intermediate commits cannot expose a
   second authority;
6. the manifest, parent D0, active card, and CURRENT_STATE pointer agree.

## Stop / NoSafeSlice

Return to design review without implementation if any of these appears:

- an exact owner or production caller cannot be identified;
- a replacement needs a second issuer, AST/name/ordinal re-pairing, or a
  compatibility retry;
- a required field can be dropped through a retained/test/Raw terminal;
- a post-terminal consumer must classify App/ProgramRuntime again;
- a guard can only be prose or a broad text count with no symbol boundary;
- C0 needs Builder physical work before the typed input is admitted;
- the proposed work expands beyond this declared census boundary.

The next implementation decision is not selected by this card. It opens only
after this manifest is accepted and the work mode is explicitly changed from
`design_stop`.
