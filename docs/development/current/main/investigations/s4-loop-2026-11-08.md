L3. 元source transactionを借りる入口に別Txnを並べず、成功/失敗ともpending PHIを残さない。
L4. 最初の失敗、strict/devの診断policy、rollback失敗の情報を既存境界で保持し、検査を弱めて互換にしない。

L6. cleanupのNormal/Fault後の実際の終端をCFG predecessorとし、cleanup前のsource辺で代用しない。
L7. 一つの関数のCFG/SSA sessionをprefix・loop・子loop・Fault・cleanupに使い、全辺が揃う前にseal/finishしない。
L8. call/Fault/Text/Dynamic/借用は元の検査済みInvocation/Expression packetを共通入力に保持し、scalar/Unknown/偽Bindingへ変換して通さない。
L9. 選択は効果より前に一度だけ行い、既存優先順を無条件の全候補Overlap拒否へ替えず、選択後の失敗でretryしない。
L10. route_loopへ元resolverのloop siteを入口から渡し、ASTのcondition/bodyからsiteを逆引きする処理と同形loopの曖昧拒否を削除する。
L11. 置換した関数/専有adapterは同じseriesでcaller-zeroと削除を確認し、共通処理を含むproduction純減で閉じる。
L12. 329＋1459のMIR比較、229入力/apps100/384の既存成功、既存の安全性検証を再利用し、空filter/marker/timeoutをPASSにしない。
L13. B1の既存strict/dev＋planner-required診断はPhiTxnのpending tokenとabort結果へ投影し、元の失敗とrollback失敗の両方を保持して元のrefusal境界を変えない。
L14. PHIの先行定義の途中の失敗も同じTxnでabortし、source sessionのTxnは借りるだけで移管・二重commitしない。
L15. portable LoopOperationV1のSerialize schemaと公開MIR/ABI/descriptor/C shimの形は変えず、所有のsource走査やparked laneは変更しない。

L16. 空incomingのpatchはprovisional PHIを完了した証拠にせず、非空のpatchまたは明示rollbackまで同じTxnのpending tokenを保持する。

L17. located invocationの元parent source receiptからsiteを渡し、siteの無いRawLegacy入口では形/番号から補わず名前付き拒否とし、既存成功入力に影響すればその呼ぶ側のsource transportを先に接続する。

## B2の機械的な接続規則

L18. 元sourceが検証した型付きHeader/Afterの発行順とValueIdを保持し、共通Binding SSAは同じPhiTxnで発行したtokenを採用する。
L19. 各source辺とcleanup後の実終端の照合に成功した定義だけを共通Binding SSAへ登録し、family専用のincoming生成mapを作らない。
L20. 共通control sessionはFunctionOwned stateに保持して子関数への入場で隔離し、子loopは親と同じsessionを借り、いずれかの失敗は同じ関数のpending PHI全体をabortする。
L21. 全incomingが揃ったblockのSSA完了にはcanonical CFGの実predecessor witnessを使い、関数出口で同じpredecessorを再照合してから全CFGと一つのPhiTxnをfinishする。
L22. prefixと検査済みInvocation/Expressionの既存sealed blockを共通CFGへ引き継ぐ時も実terminatorとcached predecessorを照合し、blockを再openせず、sourceの意味をMIRから推測しない。
L23. 共通sessionがある間のblock生成と通常Jump/BranchはそのCanonicalCfgSessionを使い、未選択の関数の既存経路は変えない。
L24. source loopの局所完了はそのscopeのPHIとsource対応だけを検査し、外側loopのpending tokenを消費したり関数のtransactionをcommitしたりしない。

L25. checked sourceのBranchが持つ空CarriersOnly引数と既存の書込み一回検査を保ち、CFG共通化でNoneへ替えたり公開MIRの形を変えたりしない。

L26. retained source Recipeの肯定済みselectionがある関数はbody入口で同じcontrol sessionを開き、loopへ到達してからprefixのCFGを直す形にしない。
L27. cleanupの前方参照edgeは同じCFG writerが元instructionのまま記録し、後で実blockを作る時に既存terminatorの実incomingを初期predecessorへ登録し、最終verifierでcacheを修復しない。
