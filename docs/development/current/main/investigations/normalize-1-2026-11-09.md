## 規則

N1. Fault枠の要否は既存CheckedExpressionEvaluationV1が元のoperation loan・Core law・field source・一時値Endの責任から答える。
N2. opcode・物理型・receiver名・PureRead・TrivialBoolだけを非Fault証明にしない。
N3. exact scalar copy・元の整数演算法則・exact i64比較は既存の証明を使い、call・checked field・所有一時値のEndには従来の枠を残す。
N4. Print等の行き先自身のFault責任とroot process-result/disposeの既存枠は保ち、式から最終consumerまで枠不要と証明できる場合だけ除く。
N5. 非Faultの式は同一blockで一度評価し、式のための枠・入口Jump・cleanup block・出口Jumpを作らない。
N6. 実在しない命令や値を境界に偽装せず、既存projection内で実在するCFG境界と同一block範囲を区別する。
N7. sourceと参照・順序・未所属命令・copy依存の検査を両形で実行し、最終化後は既存PhysicalBoundaryの全命令列照合を保つ。
N8. 共通field読取は元のreceiver/home/site・宣言または閉SUM・全writer・OwnedReadyの成功write/支配を保持し、旧terminalが許可した範囲だけを接続する。
N9. Addの左右・元operator・結果・Returnの同一性とaffineな読取消費は共通operation/field/return検査が引き受ける。
N10. 新しい正規形型・分類器・台帳・progress型・Fault計画owner・raw/checked選択器は追加しない。
N11. 置換した専用型・欄・hook・dispatch・writer・validatorは同じseriesでcaller-zeroを確認して消す。
N12. 拒否変化b=0と出力/exit不変を守り、変更MIRを全件列挙して命令・block・Invoke・Fault辺が増えないことを確かめる。
N13. 整形後production純減を追加処理と移動先込みで測り、未達なら同じ範囲の責務分担を見直して理由を報告する。

## 空のscalar再代入の対応

最初の全1,788本比較で `audit-s3a/in/r3.hako` が新しく拒否された。原因は、非Faultの参照だけの式が正当に命令を所有しない場合も、prefix group が一律に空列を拒否していたこと。既存 EvaluatedBinding の immutable original が空で、inline範囲と同じ source の非Fault証明がある時だけ空列を許可し、その後の owner・site・source/frame同一性・reference/assignment receipt・最終命令列の照合は残す。既存のprojection test内で分岐内の再代入の正例と、最終MIRへの未所属命令挿入の拒否を追加し、同familyの3件がPASSした。

## root consumer 境界と非rootへの適用

rootのframe削除は停止した。既存Lifecycle V4 admissionはrootにframeを一つ要求し、root_i64の終了値・dispose処理もそのframeを使用する。frameなしのStatic V2へ公開すると出力は一致しても、固定suiteのownership_copy_minが要求するLifecycle V4 traceを失い7/8になる。consumerの公開契約を変えずにrootを軽くする証拠はないため、root source publicationの試作は戻した。

既存ledgerのsealed root ownerと式のsource ownerが異なる通常関数だけで、既存queryが非Faultと証明する式をinlineにする。root/owner不明は従来通り。calleeのcall、Print、owned result、checked field等のFault/cleanup要求も従来通り保持する。これはrootに新しいframe要求を作る判断ではなく、既存consumerまでframe不要と証明できる範囲の限定である。source lawsのみでroot process ABIのframeを削除できるとはしない。

旧Static V2公開判定とpublication testは基点のまま保持する。ダミーframe、lifecycle flagの偽装、MIR形や関数名によるbackend選択を足さない。nonrootのinline initializerを実際に通るsourceで、最終命令列の挿入・重複・削除・順序変更の拒否を既存testに残す。
