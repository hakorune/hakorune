# 正規化1: 非Fault scalar評価とterminal fieldの合流

基点 `a74b40ba59`、branch `normalize-1`。実装前にread-only worker 3人で調査した。
受理・拒否文言・出力・所有/Fault/独立検証を保持し、既存の証拠と評価器を使う。

## 規則

N1. Fault枠の要否は既存CheckedExpressionEvaluationV1が元のoperation loan・Core law・field source・一時値Endの責任から答える。
N2. opcode・物理型・receiver名・PureRead・TrivialBoolだけを非Fault証明にしない。
N3. exact scalar copy・元の整数演算法則・exact i64比較は既存の証明を使い、call・checked field・所有一時値のEndには従来の枠を残す。
N4. Print等の行き先自身がFaultを起こす場合はその責任の枠を保ち、式が非Faultであることから行き先まで非Faultとしない。
N5. 非Faultの式は同一blockで一度評価し、式のための枠・入口Jump・cleanup block・出口Jumpを作らない。
N6. 実在しない命令や値を境界に偽装せず、既存projection内で実在するCFG境界と同一block範囲を区別する。
N7. sourceと参照・順序・未所属命令・copy依存の検査を両形で実行し、最終化後は既存PhysicalBoundaryの全命令列照合を保つ。
N8. 共通field読取は元のreceiver/home/site・宣言または閉SUM・全writer・OwnedReadyの成功write/支配を保持し、旧terminalが許可した範囲だけを接続する。
N9. Addの左右・元operator・結果・Returnの同一性とaffineな読取消費は共通operation/field/return検査が引き受ける。
N10. 新しい正規形型・分類器・台帳・progress型・Fault計画owner・raw/checked選択器は追加しない。
N11. 置換した専用型・欄・hook・dispatch・writer・validatorは同じseriesでcaller-zeroを確認して消す。
N12. 拒否変化b=0と出力/exit不変を守り、変更MIRを全件列挙して命令・block・Invoke・Fault辺が増えないことを確かめる。
N13. 整形後production純減を追加処理と移動先込みで測り、未達なら同じ範囲の責務分担を見直して理由を報告する。

## 非Fault scalar接続

既存sourceの問い合わせで枠とCFG境界をoptionalにし、同一block範囲・copy依存・source順序・最終の全命令列を照合する。
実際に共通initializerを通るwitnessは `local b = copy a + 1`。単純な `a + 1` とtyped fieldのLocalは、旧scalar-expression laneへ譲る場合があるため、この接続の証拠に数えない。
Loop側の外側entry/endも同じsource問い合わせに従って照合する。既存2回帰を修正し、focusedは72 PASS・既知8 FAIL、新規FAILなし。
同一family内の計算済み引数について、構築/消費と物理照合を分けて既存巨大ファイルを縮めた。移動行は純減に数えない。
新しい改変検証は既存initializer projection testへ1件追加し、命令の挿入・重複・削除・順序改変が最終consumerで拒否されることを確認する（既存証拠だけでは新しいinline区間を実際に通らなかったため）。

## Add / field Return 合流の試作結果

- 既存の `LocalReadProgress::Emitted` へ元の `ExactLexicalReadV1` を保持し、OwnedReady の既存 storage 問い合わせへ raw/checked 選択を委譲した。receiver の owner/site/binding/base、`loan_forwarded_copies` と installed local、store Normal dominance、copy→read の最終対応は保持した。型付き allocation-only の Add / field Return は基準と命令数・block数・Invoke数が同じになった。
- Dynamic allocation-only の `return pair.left + pair.right` は、命令72→94、block50→72、Invoke18→26。旧 raw 読みは基準 EXE の独立検証で `object-field-read-definition-invalid`、試作は checked 読みにより EXE exit50。閉じた SUM だけから旧 raw を正当化する法則は足さない。段階(ア)は「MIRが重くなる」により停止。
- 同じ Dynamic source の `return pair.left` は、命令75→81、block55→61、Invoke20→22。基準・試作とも EXE exit30。段階(イ)も「MIRが重くなる」により停止。
- 主な残件は `selected/expression_value.rs` の式 Fault suffix と `selected/root_graph.rs` の root End suffix を同じ既存 composer で一度だけ生成する接続。`cleanup.rs::finish_body_cleanup` の空 Normal continuation も重複する。root graph の Emitting と `retain_return_expression_v1` の Prepared の順序を整理し、同じ cleanup graph の入口を貸す必要がある。新しい公開形式が不可避という判断ではない。
- nested Return の試作には `stage_result_field_paths_v1` と Statement field-path の同一 site への二重登録による `result-path/stage-conflict` も残った。二つの canonical source を exact geometry・descriptor・元 Return site で照合し、一つの progress row を使う責務が未接続。既存の nested source / Fault mutation test は改変せず保持した。
- 試作は patch と実測ログへ退避して適用を戻した。専用 terminal 型・field 台帳・consult は現役 caller が残るため削除していない。追加した共通処理の純増を専用一式の削除で回収できていないため、series の production 純減は未達。段階(ウ)の最終 binary で全体検証し、報告に数値と残件を記す。

## 空のscalar再代入の対応

最初の全1,788本比較で `audit-s3a/in/r3.hako` が新しく拒否された。原因は、非Faultの参照だけの式が正当に命令を所有しない場合も、prefix group が一律に空列を拒否していたこと。既存 EvaluatedBinding の immutable original が空で、inline範囲と同じ source の非Fault証明がある時だけ空列を許可し、その後の owner・site・source/frame同一性・reference/assignment receipt・最終命令列の照合は残す。既存のprojection test内で分岐内の再代入の正例と、最終MIRへの未所属命令挿入の拒否を追加し、同familyの3件がPASSした。

## frameless scalar の source-bound 公開経路

最初のEXE比較で、14入力が不要frameの消失により `ExplicitCompatibility` へ降格した。既存 `root_scalar_read` の公開判定を `has_source_scalar_root_v1` / `validate_source_scalar_root_v1` へ整理し、旧 plain bound-read の条件をそのまま保持した上で、全出口が封印済み Integer scalar/literal であり、元の共通評価が同じqueryで非Faultと証明されている時だけ公開を保持する。literalだけの出口集合では、保持済みroot/Loopのinitializer・rebind source packetを証拠とする。physical opcodeからの推定、lifecycle存在flagの偽装、dummy frame、legacy retryは行わない。既存Static V2の形を使い、finished projection・root cleanup・独立した最終検証は保持する。元のbound-read正例、評価付きmixed return、loop literal exits、評価証拠のないmixed returnの拒否を既存publication testに統合し、focused 3件PASS。

LoopAfter・LoopHeader・BranchNormal の既存scalar Returnは意図的に `original_read=None` とする。公開判定では元のsource kindとloop/branch packet、完全なfinished boundaryを使い、架空のCurrentScalarReadを作らない。旧bound-read条件以外には実在する非Fault評価のwitnessを必須とし、PHI returnを含む正例と、witnessのないmixed returnの拒否を同じ既存publication testで確認した。
