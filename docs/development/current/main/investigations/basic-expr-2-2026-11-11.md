## 実装前に固定する規則

- C1. 式は元の source と点で有効な値の証拠を共有評価で一度照合し、各 consumer は結果の行き先と制御辺を渡す。
- C2. 整数の複合式は演算とオペランドの既存契約を合成し、既存の正規 EXE が使う命令と順序を維持する。
- C3. CodePointCount の sealed source 証拠を Return と比較オペランドへ運び、非 Fault の StringLength と実行可能な経路ごとの End を維持する。
- C4. Array の read・write・End は同じ取得元を照合し、現行の独立検証が表せない provenance が必要ならその境界を記録する。
- C5. String field の比較は既存の独立した Text 取得を評価順に置き、消費後の End と比較の意味を維持する。
- C6. take は元の Home と callee への移転を一度照合し、入口前の Fault と移転後の Normal・Fault で正しい側が End する。
- C7. null 比較の計画は各受理経路の証拠から発行し、既存の受理・拒否・生成形を維持する。
- C8. 比較 issuer の既存 domain、結果、suspension、Fault、lifecycle と説明を維持する。追加指示 (オ) の整形後 −109 行は報告に計上し、今回の基点からの差分とは分けて記録する。
- C9. 型付き static Call の式オペランドは既存の executor が選んだ同じ source から正確な i64 入力を借り、両 owner の Completion と独立 packet 検証を経て値を渡す。
- C10. raw の null 比較は、元の条件の点で生きた取得または受領結果を照合し、既存の Bool frame と子の評価順を維持したまま比較命令の計画だけを借りる。
- C11. 式計画の空の欄は共有の生成箇所で初期化し、各発行元が証明した結果の欄だけを入れる。
