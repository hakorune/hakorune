| 失敗 | 名前の付いた拒否。黙って別の道へ回らない。部分的に作った物は捨てる |

最初の版(v1)の範囲は、**selfhost のコンパイラ(`.hako`)が使う機能を、正しく動かすのに要る物を閉じた部分集合**にする(決定 6)。「その構文を書くか」ではなく、「使う機能が要る契約」で切る。例えば `fini` を書かなくても、Box・Array・Map・String の責任の終了は要る。`cleanup` を書かなくても、途中で Fault した時の一時値の終了は要る。

| 種類 | v1 が下ろす形 |

## 2. 段(5 つ)

```
AST
 │ 1 宣言の表        宣言の同一性・明示された署名・名前空間・別名を、1 回だけ表にする
 ▼
 │ 2 意味の確定      関数ごとに、型の付いた本体と、実行の契約を決める。ここで拒否も決まる
 ▼   ─────────────  ここから下は、source の意味を決め直さない
 │ 3 下ろす          1 本の再帰が、確定した本体を順に歩いて、1 つの作業場へ命令を書く
 ▼
 │ 4 仕上げ          残る出口と終了の処理を閉じる。未完成の PHI や block が無い事を確かめる
 ▼
 │ 5 検証して公開    完成した MIR を、段 2 の契約と照らして検証する。全部通ったら、まとめて公開する
 ▼
MirModule
```

| 段 | 確定させる物 | しない事 |
|---|---|---|
| 1 宣言の表 | 宣言の同一性、**明示された**署名、名前空間、別名 | 本体を読む事。書かれていない型を決める事(それは段 2) |
| 2 意味の確定 | **確定した関数** = 型の付いた本体 + 解決済みの呼び出し + 値と置き場の操作 + 評価の順 + scope + 制御の行き先 + 所有と失敗の**規則** | `ValueId`・block を発行する事 |
| 3 下ろす | その契約に対応する、実際の命令・CFG・SSA・要る所有の操作。**対応の記録**(9 節) | source の意味を決め直す事。形を見分けて受け付けるかを決める事 |
| 4 仕上げ | 出口ごとの終了の処理、未完成の PHI や block が無い事の確認(PHI を作って閉じるのは、段 3 の作業場) | 新しい計画を立てる事 |
| 5 検証して公開 | 通すか、捨てるか | 直す事 |

**段 2 と段 3 の間の線が、この設計の中心である。**

> 段 3 から後ろは、source の意味を決め直さない。
> 決まった意味を実現するための、配置・制御・値・所有の具体の関係は、後ろの段で計算して、検証する。

- 段 2 は、block を発行しなくても、分岐・scope・出口・効果の関係を持てる。構造のある、型の付いた本体でよい。2 本目の物理の CFG を作らない。
- 「意味の持ち主は 1 つ」は、「1 回の走査で全部決まる」ではない。戻り型の推論や相互再帰は、段 2 の中で、要るだけ解く。
- 所有は、段 2 が**規則**を決め(この引数は借りて渡す、この代入は持ち分を得る)、段 3・4 が、どの値・どの辺で実現するかを決める。段 3 が、借りを所有へ勝手に読み替える事は、しない。

## 3. 正本の表(何を、どこに 1 つだけ置くか)

| 事実 | 正本 |
|---|---|
| 宣言 | 宣言の表(段 1) |
| この名前の使用は、どの束縛か | 確定した関数(段 2) |
| この式の型 | 確定した関数(段 2) |
| この呼び出しの呼び出し先と署名 | 確定した関数(段 2) |
| この操作で、所有はどう動くべきか(規則) | 確定した関数(段 2) |
| この束縛の、今の値 | 段 3 の作業場の、1 つの表。関数を閉じたら消える |
| 実際に、どの値がどの責任を持っているか | 完成した MIR(明示の取得・移転・終了の操作) |
| ある値が、別の値と同じ定義から来たか | 完成した MIR(Copy と PHI をたどる) |

決まり:
- 事実は、正本が 1 回書いて、後ろが参照で読む。段ごとに包み直さない。別の型へ詰め替えない。
- **同じ対象に、段ごとの別の ID や語彙を作らない。** 意味の違う対象(source の型、所有の区分、MIR の表現の型、ABI の表現)には、要る識別子と語彙を使ってよい。その時は、正本の型から、責任ごとの投影として、明示して導く。
- source との対応を、どの ID からも失わない。

## 4. 事実と、1 回だけの事

| | 例 | 持ち方 |
|---|---|---|
| 事実 | 型、束縛、呼び出し先、署名、所有の規則 | 不変。何度読んでもよい。許可の形に包まない |
| 1 回だけの事 | 発行、所有の責任、公開 | 下の 3 つ |

1. **発行**: 1 つの書き手と、構造のある再帰で、重複を起こしにくくする。**再帰だけでは証明にならない**(子を 2 回呼ぶ、飛ばす、順を変える、違う block に置く、は起こりうる)。確かめるのは、段 5 の検証である(9 節)。token を配って守らない。
2. **所有の責任**: MIR の上の明示の操作と、8 節の 1 つの規則で守る。
3. **公開**: 段 5 が 1 回だけ行う。

## 5. 式(入口は 1 つ)

- 式を値として下ろす入口は 1 つ。**式が置かれた場所(文、初期化、引数、receiver、条件、return)で、入口を分けない。** 場所が決めるのは、結果を「どう使うか」だけ。
- 結果の形: **正常な続きがあるか**を、必ず表す。
  - 続きがある: 続く block、値(または Unit)、型、責任の情報(持っているか、借りているなら何に支えられているか)。
  - 続きが無い: `Return` や Fault で終わっている。存在しない値を、後ろの引数や PHI へ渡さない。
- 評価の順は、仕様のとおり、左から 1 回ずつ。
- 短絡(`&&`、`||`)と block の式は、分岐と合流になる。
- **値として評価する事と、置き場として評価する事は、別の操作**である(7 節)。これは、場所ごとの道ではない。
- 式の種類 × 置かれた場所、の表を作らない。

## 6. 呼び出し(1 つの形)

決まりは 1 つ: **先に呼び出し先を決める。次に、入力を仕様の順に 1 回ずつ評価する。呼ぶ。結果を受ける。**

解決済みの呼び出し(段 2 が決め、段 3 が読む):

```
呼び出し先   解決済みの宣言 + 署名(または、実行時に決まる、という契約)
入力         receiver(要る時だけ。役割つき)+ source の順の実引数。各入力の渡し方(借りる、渡す)
結果         型、所有の区分、借りなら何に支えられるか
失敗         Fault しうるか
```

段 3 の手順:

```
receiver と各実引数について、仕様の順に:
    式として下ろす(5 節の入口)
    その入力を、要る間、有効に保つ(field や要素から読んだ物は、ここで +1)
    次の入力へ進む
全部そろったら、Call か Invoke を 1 つ書く
結果に要る責任を確保する
要らなくなった入力の保護を終える
```

- `f(a.child, g())` で、`g()` が `a.child` を消しうる。**全部の引数を評価した後に守るのでは、遅い。** 評価した直後に守る(ADR-003 の決まりと同じ)。
- 途中の入力の評価が Fault した時は、それまでに取った責任だけを片付ける。外側の呼び出しは、しない。
- 結果が、入力に支えられた借りなら、呼び出しの直後に、その入力の保護を終えない。

種類ごとに違ってよいのは、4 つだけ。違いは data で持ち、道を分けない。

| 違い | どこで決まるか |
|---|---|
| 呼び出し先の決め方(名前、`me`、型、別名、値) | 段 2 |
| receiver が要るか | 段 2 |
| Fault しうるか | 段 2 |
| ABI での並べ方 | MIR より後ろ |

- receiver を「0 番目の実引数」に潰さない。source の引数の番号、receiver という役割、ABI の位置は、別の物。
- `static box` の中の `me.m()` に、偽の receiver を作らない。Direct を Method に見せかけない。
- `new` は、「確保 → field の初期化 → `birth` → 公開」の決まった並び。`birth` を呼ぶ所は、上の同じ手順。途中で Fault した時は、初期化が済んだ部分だけを片付ける(15 節)。

## 7. 文と制御

| 文 | 下ろし方 |
|---|---|
| `local x = e` | 式を下ろして、束縛の今の値にする。所有の規則(8 節)を適用する |
| 代入 | 置き場を先に決めて、式を下ろして、書く。古い値の責任を終える |
| `if` | 条件を式として下ろして、分岐。合流は作業場が作る |
| `loop` | **形を見分けない。** 条件・本体・戻り・出口を、構造どおりに作る |
| `break` / `continue` / `return` | 抜ける scope の終了の処理をして、決まった行き先へ |

- **置き場**は、生の番地ではない。次を決めた物である: 何を 1 回評価したか(base、添字)、何を保つか、いつ範囲を検査するか、いつ実際に書くか。`array[i] = make()` で、`make()` が同じ配列を変えうるので、先に取った要素の番地が最後まで有効とは限らない。複合代入の、古い値を読む時点と右辺の順も、言語の契約として固定する。
- **変数と PHI の持ち主は、作業場の 1 つ。** 束縛ごとに今の値を持ち、合流と loop の入口で PHI を作る。loop の構築の途中で、仮の PHI を本体から参照してよい。PHI の入力は、前の辺が全部分かった所で、作業場が閉じる(未完成の台帳を、後ろの段へ渡さない)。loop の入口の PHI は、Resolve が出す「その loop の中で代入される束縛」の集合にだけ作る。**未完成の PHI を、完成した関数として公開しない。**
- **loop の家族は、受け付けるかどうかを決めない**(決定 4)。家族の見分けは、診断と最適化のためだけ。ただし、一般の loop の契約(loop をまたぐ初期化、値の合流、`break` の行き先、`continue` で抜ける scope、範囲 loop の境界と増分の評価)は、段 2 が確定する。
  - 「Recipe」には 2 つの意味が混ざっている。**家族に当たったから受け付けるための専用の計画**は、受け付ける条件から外す。**評価の順・全部の出口・所有の責任を確定した論理の計画**は、段 2 の確定した関数として残す。

## 8. 所有

- **所有の規則を実装する責任は、1 つに集める。** 式や文の下ろし方は、自分の RC の決まりを持たず、共通の操作を使う。
- その規則は、次の全部に適用される(呼び出しと出口だけではない)。

| 操作 | 要る所有の処理 |
|---|---|
| `local b = a` | `b` が持ち分を得る(または、認められた移転) |
| `b = c` | 新しい値を保って、古い `b` の責任を終える |
| `me.f = b` | field へ責任を渡して、上書きされた値を終える |
| Array / Map への保存と削除 | 入れ物の責任の取得・移転・終了 |
| 呼び出しの入力 | 評価した直後から、要る間、保つ(6 節) |
| `return` | 返す値を守ってから、scope を片付ける |
| scope の終わり、`break`、`continue`、Fault | 片付けを内から外へ。`local` を宣言の逆の順に |
| `new` の途中の Fault | 初期化が済んだ部分だけ |

- `+1` があふれた時は Fault(ADR-003)。だから `local b = a` にも、失敗の道がありうる。
- **「持っている / 借りている / 数えない」の 3 つの区分だけでは、検証できない。** 次を区別できる表現が要る: どの責任を取ったか、どこへ移したか、借りは何に支えられるか、どの辺で終えたか。MIR の上の明示の操作(取得・移転・終了)と、責任を表す値や置き場で表す。段ごとの loan の包みは、使わない。
- 所有の model が変わる時(ADR-002 へ戻るなど)、直す所を 2 つに閉じる、とは約束しない。何が合法かまで変わるからである。約束するのは、「所有の規則が 1 つの責任に集まっていて、変える時の範囲が見える」事。

## 9. 検証と義務

検証は 3 種類。

| 種類 | 見る物 | 例 |
|---|---|---|
| a 形 | MIR と、その型の情報 | CFG、SSA、支配、PHI と前の辺、Invoke の Normal/Fault の形 |
| b 所有 | MIR(所有の操作・呼び出しの契約・支えが、MIR に明示されている事が前提) | 対象・移す先・実際の道ごとに、責任を追う。+1 と −1 の総数が合うだけでは、足りない |
| c source との対応 | MIR + **段 2 の契約** + 段 3 の対応の記録 | 下の表 |

**分担**:
- **何が起きるべきかは、段 2 の確定した関数が正本。**
- **それを、どの命令・辺・値が実現したかは、段 3 の対応の記録。**
- 検証は、対応の記録を手がかりにしてよいが、期待する演算・呼び出し先・分岐・順まで、段 3 の自己申告を信用しない。(`return a + b` を、段 3 が誤って減算で書き、「この減算の operand は a と b」と記録しても、通らない事。)
- 検証は、作る側がたどった証拠の道を、もう 1 度歩かない。

義務は、1 つの体系の中の、少しの種類である。全部を同じ小さい組に押し込まない。

| 義務の種類 | 確かめる事 |
|---|---|
| 値と演算 | 正しい演算、定数、実際の operand、定義との関係(Copy/PHI を越える出所は、完成した MIR から導く) |
| 呼び出し | 呼び出し先、receiver、実引数とその順、結果、**実行される条件** |
| 制御 | 条件の向き、分岐の先、loop の戻り、`break`/`continue`/`return` |
| 効果 | 書く先、評価の順、条件つきの実行、余分な実行が無い事 |
| 終了 | Normal と Fault での責任、片付けの対象と順、返す値の保護 |

- **数が合うだけでは、足りない。** source に呼び出しが 2 つあって、1 つを落として 1 つを 2 回対応させても、数は 2 である。確かめるのは、「どの source の操作の、どの役割に、対応が有り、重ならず、余分な効果が無いか」。
- **実行される条件と順も、義務である。** `if enabled { send() }` を、`send()` を先に呼ぶ形に下ろしても、呼び出しの数・呼び出し先・引数は合う。
- 「source の node 1 つに、命令 1 つ」は、決まりにできない(`new` は 1 つの式から複数の操作になる。片付けは、出口ごとに置かれる)。操作ごとに、認める展開と、実行の回数の関係を決める。
- 作る側が、作りながら同じ意味の検証をやり直す層は、置かない。ただし、作業場の局所の整合の検査(閉じた block へ書かない、など)は、置いてよい。

## 10. この設計に無い物

- 家族ごとの専用の道。形を見分けて、受け付けるかを決める事。
- 式の「場所ごとの枠」。呼び出しの「種類ごとの packet」。
- 事実を、段ごとに貸し直す包み。同じ対象の、段ごとの別の語彙。
- 新しい道が駄目なら古い道へ戻る事。失敗した後の再試行。
- 名前・MIR の型・backend の成功から、意味を推測する事。AST の書き換え。
- 段 2 が、命令や block を作る事。段 3 が、意味を決め直す事。
- 作る側が運ぶ、値の経路の証拠。

**今ある MirBuilder を、責務ごとにまとめて、古い処理を消す。** 別の builder を、横に作らない。

- 2026-11-17 に、別の入口で新しい builder を作って比べる事を試した。数と Bool の範囲は小さく書けたが、builder が 2 つ並び、古い code は 1 行も減らなかった。メンテナの決定で、撤去した(code は git の履歴にある。分かった事は `docs/development/current/main/investigations/mirbuilder-blueprint-work-2026-11-17.md`)。

作業の単位:

- 「この source の形を通す」ではない。**「この責務の処理を 1 つにまとめて、使い手を切り替えて、古い処理を消す」**である。
- 今の入口(既定の道)を保ったまま、中の 1 つの責務を置き換える。置き換えた古い実装・中継・専用の test は、同じ回で消す。途中の共存を、完成形にしない。
- 整理の回は、受け付ける範囲を広げない。新しい機能は、別の回にする。
- 1 つの置き換えは、3 回で閉じる:

| 回 | やる事 | 閉じる条件 |
|---|---|---|
| 1 設計 | 今の使い手、まとめた後の入口、残す保証、**消す関数・型・分岐の名前**を決める | 消す物と、その保証の移り先が、対応している。決まっていない言語の決め事・新しい公開の MIR・新しい機能が、要らない |
| 2 置き換え | 使い手を共通の処理へ切り替えて、中継と重複を消す | 前から通る入力の出力と exit、前からの拒否が、変わらない |
| 3 監査 | 残った参照・専用の test・一時の接続を確かめる | 対象の古い処理が消えている。足した分を含めて、本体と test の合計が減っている |

- 止める条件: 新しい言語の決め事や公開の MIR が要る。古い処理を残さないと成り立たない。つなぎの部品が増え続ける。**止めた時は、同じ名前の回を延長しない。** 境目を選び直す。
- 数える物は 4 つ: 対象の本体の純増減、消えた古い実装の名前、同じ意味を決めている場所の数、残っている一時の接続の数。
- **消せない事は、責務が分かれていない証拠である**(メンテナ 2026-11-17)。ある処理を消そうとして、周りを直さないと消せない時は、その周りと、責務が混ざっている。消せない理由(誰が、何のために使っているか)を書き出して、そこを先に分ける。「念のため残す」で済ませない。
- 消す事を、怖がらない。消した物は git の履歴に残る(`docs/development/RULES.md` 8 節)。「参照のため」「念のため」に、使わない実装を残さない。残すのは、分かった事の文である。
- 「MirBuilder の整理が終わった」と、「selfhost に要る未実装の機能ができた」は、別の完了である。後ろを、前に足さない。
- 古い builder の lib の test(決定 7): archive しない。内部の形(packet の field、block の並び、道の名前)だけを見ている test は、その code を消す回で、一緒に消す。言語の動きを見ている test は、`.hako` と期待の出力に書き直してから、消す。ずっと赤い test は、何も守っていないので、分類して消す。

## 18. 3 つの失敗を分ける

| 失敗 | 誰の事か | 出し方 |
|---|---|---|
| 不正な source(型が合わない、名前が無い) | 書いた人 | 段 2 の compile error |
| まだ作っていない機能 | 言語の実装 | 段 2 の、名前付きの拒否 |
| 段 3 から後ろで、決まった契約を実現できない / 不正な SSA / 義務を落とした | コンパイラの不具合 | 内部の誤り。「この形は未対応」にしない |

3 つ目を「未対応」として扱うと、下の段に、また形ごとの受け付けの制限が生まれる。

この 3 つの他に、source の適否ではない停止が 2 つある: **対象・環境の制約**(backend が未対応、要る runtime や外部の library が無い。その能力を確かめる 1 つの所が出す)と、**実行時の失敗**(生成した検査と runtime が出す)。Resolve が受けた source を、後ろの段が自分の「形の条件」で断らない、という決まりは、不正な生成物を検証が止める事を、妨げない。

## 21. 作り方の決まり: 再帰で書く(メンテナ指示 2026-11-17)

MirBuilder の仕事は、source の木を、上から下へ再帰して下ろす事である。難しい問題ではない。今の code が大きくなったのは、問題が難しいからではなく、**形を先に見分けて、形ごとに道を作った**からである。

```
式を下ろす(node):
    リテラル → 定数を 1 つ
    a + b    → a を下ろす、b を下ろす、足す
    f(x, y)  → x を下ろす、y を下ろす、呼ぶ
    if       → 条件を下ろす、分岐、両方を下ろす、合流
```

| | 再帰で書く | 形を見分けて道を作る |
|---|---|---|
| `f(g(x))` | 「引数を下ろす」が、自分を呼ぶだけ | 「引数が呼び出しの時」の道が要る |
| loop の中の `if` | 「文を下ろす」が、自分を呼ぶだけ | 「`if` を含む loop」の家族が要る |
| 形を 1 つ足す | 決まりを 1 つ足す | 今ある全部の道との組み合わせを足す |

決まり:
1. **node の種類ごとに、下ろす決まりは 1 つ。** 子は、同じ入口を呼んで下ろす。子が何であるかを、親が見分けない。
2. **「この形の時だけ」の分岐を、足さない。** ある入力を通すために、その形だけを見る条件(子の種類の組み合わせ、深さ、置かれた場所、呼び出しの種類、app や file の名前)を書きたくなった時は、止める。足りないのは、node の種類の決まりか、共通の操作の方である。
3. **種類 × 場所、種類 × 種類の表を、作らない。** 表ができ始めたら、再帰から外れている。
4. **所有・片付け・検証も、同じである。** 難しいのは決まりを決める所で、作る所ではない。決まりは 1 か所に書いて、再帰のどこからでも同じ操作を呼ぶ(8 節)。
5. 速くするための特別な形(loop の家族など)は、MirBuilder の外の最適化で扱う。受け付けるかどうかには、関わらせない。

## 22. 監査で数える物と、やめる線(メンテナ指示 2026-11-17)

毎回の監査で、次を数えて、前の回と比べる。

| 数える物 | あるべき姿 |
|---|---|
| 式を下ろす入口の数 | 1 |
| 呼び出しを下ろす入口の数 | 1 |
| loop を下ろす入口の数 | 1 |
| 形を 1 つ足す時に、直す file と関数の数 | 少なく、回を追って増えない |
| 「この形の時だけ」の分岐(21 節の 2)の数 | 0 |
| 同じ対象の、別の語彙や ID の数 | 増えない |
| 設計図に無い部品の数 | 0(要る時は、先に設計図を直す) |

**やめる線。** 次のどれかが起きたら、作業を止めて、進め方を考え直す。何か月も続けない。

## 24. loop を再帰の形へ直す(決定 18〜20。2026-11-18)

### 24.1 今の code(2026-11-18 に読んだ)

- loop の入口は 1 つだが、8 本の道に分かれ、block と PHI を実際に出す所は 3 系統ある: (1) 検証済みの予定表を解釈して、すぐ MIR を出す(`source_loop_driver.rs`。葉の `local`・再束縛・条件・子の loop は、普通の下ろし方を呼ぶ)、(2) 中身を別の中間の形(plan)に全部写してから MIR にする(式も文も、専用の実装を持つ)、(3) recipe の操作を解釈する。
- **中身を、普通の文の道へ再帰する道は、1 本も無い。** carrier と PHI は、3 系統とも、中身より前に決めている。
- 普通の builder は、`break` と `continue` の腕を持たない。loop の各系統が、それぞれ持っている。
- 封をする型の SSA の構築(未完成の PHI、seal、読み出しの再帰)は、`ssa/binding` に、もうある。新しく作らない。
- `if` が 1 つにならない原因は、これである。loop の中の `if` は、先に決めた carrier の番号と合流をつなぐために、専用の定義を持つ。

### 24.2 進め方

1. 小さい 1 か所ずつ。最初は「`else` の無い `if` で、片方だけが外の束縛を書き換える」形。**1 つの回に、PHI の閉じ方の変更・普通の `if` の呼び出し・古い専用の定義と、その内部の形だけを固定する test の削除を、全部入れる。**
2. 寄せる順は、通る入力の数ではなく、「専用の道を 1 つ消し切れるか」で決める。
3. 入口の数は、「受け口」と「下ろし方を独立に決める定義」を分けて数える。
4. 形を見分けて作っていた最適化は、builder から外し、MIR を作った後の pass へ移す。外す前に、(a) その最適化が正しかった根拠を 1 例で書く、(b) 代表の入力の時間と割り当ての回数を取る。完成した MIR から判定できる材料が残らない物は、「戻せるか未確定」と記録する。
5. 受ける範囲が広がった時(古い道の形の制限が外れて、断られていた入力が通る)は、掃除とは別の変更として、止めて報告する。

### 24.2a 最初の 1 か所の判定(決定 20 を確定する条件。2026-11-18)

- **続ける根拠**: `else` の無い `if` で保たれた値が、次の周にも正しく届く。普通の `if` に、loop 専用の引数や分岐を足していない。古い定義を 1 つ消せた。普通の `if` への直しが、loop の中の `if` にも届く。
- **loop の所だけを書き直す案を出す根拠**: どの今ある系統を使っても、「中身を下ろす前に、専用の値の番号を決める」契約が要り、その契約を外せる一番小さい単位が、loop を組み立てる部分の全体だ、と追えた時。**最初の差し替えが 1 度詰まっただけでは、そうは言わない。**

### 24.3 確かめ方(この系列だけ。ほかの回は「MIR の差 0」のまま)

| 入力 | 比べる物 |
|---|---|
| block と値の番号をそろえると、MIR が一致する | それで確認できた、と数える |
| 差が残り、実行できる | 検証を通した上で、古い版と新しい版の出力・exit・見える副作用 |
| 差が残り、実行できない | 検証を通した上で、条件の向き・各辺が運ぶ値・効果の順を照合する。「検証は通った。意味の一致は未確認」と、件数を別に出す |
| 断られる | 失敗の種類が同じ |

- **想定した差(loop の組み替えで説明できる)と、理由の分からない差を、分ける。** 理由の分からない差が 1 つでもあれば、通さない。
- PHI の入力を左右で取り違えても、SSA・支配・入力の数の検査は、全部通りうる。番号をそろえる時は、**(前の block, 値)の対と、条件の真偽**を保つ。
- 作業の途中に流す「速い組」は、変えた辺を見る短い入力を、先に固定する: 0 回の反復、2 回以上の反復、`else` の無い `if` の両方向(ある周は書き換え、次の周は通らず、残った値が出力に出る)、`continue`、違う値を運ぶ `break`、入れ子、後始末の中の Fault。回の最後は、全部の入力で比べる。

### 24.4 守る事(不変条件)

- PHI の入力の元は、**実際に飛んできた block**。条件の中の呼び出しや後始末が、block を分ける事がある。`else` の無い `if` には、偽の辺の環境を渡す。`return` した腕から、合流の辺を作らない。
- `continue` は、その loop の続きへ(範囲の loop は、増分を 1 度だけ通る)。`break` は、その loop の出口へ。各 `break` と、条件が偽の辺は、その時点の値を出口へ運ぶ。0 回の反復では、入口の値が出口へ届く。
- 制御が移るたびに、抜ける scope と、生き残る所有の値を確定する。`continue` は、次の周へ運ぶ値を保ち、周の中の一時値を片付ける。`return` は、戻り値の所有を守る。後始末の中で Fault が起きても、終わった値を 2 度解放しない。
- 入れ子では、飛び先と、束縛が同じ物かどうかを、別々に追う。内側の `break` は内側だけを閉じる。内側で書き換えた外側の束縛は、内側を出た後も、書き換えた後の値である。
- 仮の PHI は、Lower の中で閉じる。φ(入口: x, 戻り: 自分)は x にする。届く初期値の無い輪から、値を作らない。Seal へ、未完成の PHI を渡さない。
