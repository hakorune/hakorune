## How To Read This File

This file is the human entrypoint, not the full historical row ledger.

Use this order for normal work:

1. Start from `docs/development/current/main/CURRENT_STATE.toml` and `CURRENT_TASK.md`.
2. Run `tools/checks/dev_gate.sh quick` or `current_state_pointer_guard.sh` unless the active card names a heavier gate.
3. Use the current-family quick index below for active selfhost / ProgramJSON / AOT work.
4. Use [`check-scripts-legacy-ledger.md`](./check-scripts-legacy-ledger.md) for the old-ledger lookup policy; use git history when a removed long-form row description is actually needed.

## Guard Growth Rule

Do not add a dedicated shell guard for every inventory or selection row.

- Add stable public entries here only when a guard is reusable, behavior-changing, or required by an active card as a public gate.
- Keep long-form one-off row descriptions out of this file; use git history when old traceability text is actually needed.
- Prefer reusable family guards, `current_state_pointer_guard.sh`, `run_row_guard.sh`, or `run_proof_app.sh` over new row-specific shell scripts.
- Measurement rows record commands and evidence in the card. Add a guard only if the measurement becomes a stable regression gate.
- Pointer updates are required for active blocker/lane transitions and behavior-changing rows; do not move current pointers for docs-only exploration rows.
