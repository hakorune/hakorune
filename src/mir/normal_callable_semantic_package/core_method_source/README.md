# Field container source and physical owners

Status: active owner; local/Birth connection under construction.
Scope: field Array Get/Count/append and Map receiver sources, original uses and physical emission.
Related: [source issuer](../ordinary_new_field_array_read_source.rs),
[Return use](../ordinary_new_borrowed_field_array_read_source.rs),
[physical read](field_read.rs), [collector](collector.rs).

One immutable CheckedFieldArrayAccessSourceV1 retains the exact self field,
original instance method, selected canonical key, batch membership and Birth
provider. Integer Element Get additionally requires the whole-Box Integer store
census and exact Integer index. Count retains the original method Arc, canonical ArrayLen/0
ArrayCount law and original all-writer loan proving the unique Plain Birth Array
provider; it requires no index or Integer elements. Incomplete, opaque, foreign,
replacement or null writer evidence cannot establish that residence. The class
name or runtime payload alone proves neither operation.

Ordinary Core Count now borrows that same checked field Count source before
Text operand premises are chosen. Direct field and original local-alias calls
keep distinct receiver/initializer sites and retain the same Count Rc through
seeds, the SUM graph and the closed Core receipt. This origin and nested
Map.keys are exclusive. Expression qualification transfers only the original
receiver subtree; the existing installation transaction checks the live parent
and the same observed alias (or matching stronger Integer residence). Input-use
closure, exact SSA receiver read, ArrayRead packet and final validation remain
separate requirements; this source proof grants no Get or execution permission.

Ordinary Dynamic Get shares the same residence/provider and alias source factory
with Count, but retains its own Get/1 operation and original method Arc. An
already-proven exact Integer Element source keeps its existing result owner;
the generic Dynamic receipt never supersedes it. The
original index site must close as signed-only in the same SUM; tagged inputs,
Bool and Text do not supply an I64 index. The existing ArrayDynamicRead target
retains DynamicToCaller and the generic Dynamic expression class. This does
not select a concrete payload or the Integer Element owner. Unknown elements
retain Other; a closed append census supplies source element alternatives,
with Null retained unless the same-field terminating guard proves bounds at
the exact Get. All-Return Text classification uses that same closed receipt;
source class facts still grant no payload extraction or execution.
Original argument correspondence is owned by the same Core receipt: Get lends
only OpaqueHandle/DynamicToCaller, never a nominal object or I64. Static and
Instance consumers reuse that predicate and retain the same original Rc;
source-plan matching does not refine the generic carrier into a nominal or
I64 expression, or supply execution permission.
Checked carrier acquisition and both-exit End must be connected before Get can
execute; source qualification alone grants neither. A sole Birth Array provider
does not prove Text elements. Before selecting a Text-copy read, the same append
and collector owners must close every mutation as Text-copy. Object-slot Get
keeps its borrowed nullable relation; neither an Arc retain nor the schema name
can turn it into an independently owned Dynamic carrier. This follows the
[existing ownership contract](../../../../docs/reference/language/ownership.md#named-array-opaque-carrier-destination-target)
and [self-contained result law](../../../../docs/reference/language/dynamic-invocation.md).

A local field alias retains the same canonical fixed-provider source and its
unique original initializer in the existing BorrowedArray local/field-read row.
Its parent entry receiver must remain live; rebinding and capture are refused.
This source origin issues neither a Home nor an Integer operation requirement.
Until the shared operation/physical owners are connected, legacy field reads
and Integer Loop append consumers reject it. Fixed Array storage is Array
residence, independent of whether the declaration had a type annotation.

Statement Text append shares Count's original Array residence and sole-provider
writer loan. Its operation retains the original Push Arc and existing
ArrayTextAppend target; the read Recipe explicitly refuses this operation.
The same Home field consult selects Text from original SUM/literal evidence and
qualifies the original argument through shared Text evaluation. A named-Array
observation retains that same source/evaluation and original statement, including
ancestry and prior Homes; it transfers no caller lease/Home. Whole input-use
closure counts its receiver/key reads once. Mandatory lifecycle prefixes retain
the append even before a physical packet exists, so missing execution cannot
silently disappear. The physical append packet, continuation/cleanup, collector,
independent final validators and source-selected Text-array End remain required.
The existing append source loan now retains either the original Loop Integer
proof/index or the same statement Text frame under its original Completion.
Entry-use lends that same Text frame, original CallArgument(0), provider census
and ancestry; integer-only emitters/collectors explicitly refuse this variant.
Both variants lend their own prior Homes to the same unwind-plan owner. This
loan alone supplies no source-selected physical append or complete element/End census.

Checked ArrayElementWrite, its passive witness and marker retain one shared
Scalar/Text payload sum. StaticText has no fake ValueId; owned/borrowed descriptors
keep their actual values through uses and SSA rewriting. The String lifetime
verifier checks Text borrowers; Text copies carry Alloc as well as Write/Control.
Final ABI writes retain Scalar(value, source kind) or the complete Text descriptor
at one exact source-issued coordinate. Canonical JSON shares String descriptor
serialization. Integer-only source packets/collectors still reject Text: the
transport alone grants no source execution, Home transfer or complete Text End.

Return use is a separate wrapper retaining all original Return sites and any
original local initializer relation. It still requires the original scalar
result/Completion law. The physical read recipe borrows the same inner read Rc;
changing Return membership never manufactures a different read or a new Home.
Normalization preserves every Return use while sharing that same read loan.

Field-return reads borrow the shared full scalar source validator without
requiring a borrowed-scalar physical Call participant. That participant's own
anchor gate remains unchanged. Original Return/Completion, declaration, grounding,
dependency closure and census validation precede lending the retained read Rc.

The raw source hook and existing ArrayRead writer remain the sole physical
owner. Element carries one index; Count carries none. The original named-array
collector checks source identity, operation/operands/destination, declared
field/provider and physical marker census. Count publication borrows only this
validated exact instruction binding; generic ArrayRead admission stays Element
only. Lifecycle JSON uses array_length with array/dst, and independent C validates
the live field residence/provider before existing nyash.array.slot_len_h. No new
Home or Fault is issued. Native single-root admission remains separate.
Local-to-Birth support must retain the original initializer/binding and checked
read, original local/Copy transport and exact Birth actual. It must pass the
existing finishing and independent final consumers. Changing Unknown to Integer
at the ABI or argument use cannot replace any of these connections.

The current extraction preserves Return admission. Local/Birth source retention,
physical correspondence and canonical app execution remain required before the
new local consumer can be accepted. No separate classification map or fallback.
